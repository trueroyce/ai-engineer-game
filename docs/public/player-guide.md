# 玩家教學

## 1. 建立職涯

從六種模板選一位角色。模板會改變起始 Token、時間、能力與壓力承受方式。

- **全能戰士**較有容錯，適合第一次遊玩或想觀察完整事件鏈。
- **真初心者**資源較緊，需要更重視需求、驗證、版本與交付證據。
- 其他模板各自偏向分析、建造、驗證或均衡；沒有唯一正解。

換一個角色會建立另一份職涯，不會直接繼承上一位角色的 EXP 與卡庫。

## 2. 選擇卡片

- 卡池共有 18 張工程卡，每案最多裝備 3 張。
- 卡片右下角顯示目前是否裝備；再按一次可以卸下。
- 卡片可能降低成本、改善成功率、補強理解或改變失敗後的恢復方式。
- 遊戲中還會出現兩次三選一成長；重整同一局不會重複領取。

## 3. 閱讀每次選擇

做決定前先看四件事：

1. **目前目的**：這一步是在理解、實作、驗證、救火，還是正式交付？
2. **成本**：Token 與時間是本次消耗；畫面會把消耗和執行後餘額分開標示。
3. **公開缺口**：未確認需求、資料相容、測試證據與負責人核准都可能阻擋交付。
4. **恢復路線**：失敗不一定要重來；補證據、縮小範圍、隔離風險或止損都可能是合法解法。

中間步驟顯示「完成」只代表該次行動完成，不代表整個專案已結案；真正結局會進入獨立結算畫面。

## 4. 四案提示

### 案件 01｜先管好自己

把模糊的功能想法變成可以驗證的範圍。先理解需求，再讓實作、測試與交付證據對上同一版本。

### 案件 02｜三份資料，一個真相

不要用多數決猜哪份 CSV 正確。先定義資料契約與來源，再分工、整合、驗證；代理做了什麼必須能追溯。

### 案件 03｜大家都說「只改一點點」

客戶後來追加功能時，原本的測試不一定還能證明新版正常。記下需求變更、重新驗證，並讓交付承諾指向正確 revision。

### 案件 04｜祖傳系統救援

先依依賴順序釐清程式、測試與部署。回滾前要確認資料／schema 相容或安全隔離；技術改動後還需要負責人核准新的交付範圍。畫面上的路線圖會顯示目前步驟與解鎖條件。

## 5. 結局與重玩

- 正式交付、有限維持、失敗與止損都是可成立的結果。
- 結局會顯示本局特色稱號；稱號描述的是你的決策風格，不會取代機械結果。
- 回到大廳後，EXP、卡庫與融合會保留；每案的 Token、壓力與時間會重設。
- 若本機版啟用了賽後教練，可在結局頁主動保存與分析；公開 Pages 版只有本機結算，不會把資料送出去。

## 6. 常見問題

### 重新整理後進度不見了

存檔綁定目前網址、瀏覽器與使用者設定檔。從不同連接埠、無痕視窗或另一個瀏覽器開啟，會看到另一份本機儲存空間。

### 案件 04 一開始為什麼只有少數選項？

這是刻意的依賴門檻，不是少載入卡片。先完成第一輪診斷／穩定化，路線圖會說明後續策略如何解鎖。

### 公開版為什麼沒有 Claude 分析？

公開站刻意是純靜態版，不探測 localhost，也不呼叫 MCP 或模型。需要分析時，請在本機 clone 版本依 `docs/mcp/README.md` 設定。
